# SerialWorkbench（WPF 串口上位机示例）

这是一个面向 **Visual Studio 2022 + WPF** 的上位机示例工程，按模块拆分了以下能力：

1. **灵活的串口参数配置**：端口、波特率、数据位、停止位、校验位、握手方式、DTR/RTS、HEX/文本模式。  
2. **串口设备动态扫描与连接控制**：扫描系统串口、连接、断开、状态显示。  
3. **数据收发与显示**：发送文本或 HEX、接收后显示原始内容。  
4. **遵循协议解析数据**：按示例协议 `AA + CMD + LEN + DATA + XOR` 解析。  
5. **数据可视化**：把解析后的数值型数据绘制成折线，并展示统计值。  
6. **数据记录与回放**：支持自动保存、手动保存、从文件读取后回放。

## 一、项目结构说明

```text
SerialWorkbench.sln
└─ SerialWorkbench/
   ├─ App.xaml                      # 应用入口
   ├─ MainWindow.xaml              # 主界面布局
   ├─ MainWindow.xaml.cs           # 主窗口代码
   ├─ Infrastructure/              # 基础设施层
   │  ├─ ObservableObject.cs       # 属性通知基类
   │  └─ RelayCommand.cs           # 命令封装
   ├─ Models/                      # 数据模型层
   │  ├─ SerialSettings.cs         # 串口配置模型
   │  ├─ SerialDataFrame.cs        # 原始收发帧模型
   │  ├─ ProtocolPacket.cs         # 协议解析结果模型
   │  └─ DataPointModel.cs         # 可视化点模型
   ├─ Services/                    # 功能服务层
   │  ├─ SerialPortService.cs      # 串口扫描、连接、收发
   │  ├─ ProtocolParserService.cs  # 协议解析
   │  ├─ RecordFileService.cs      # 文件保存/加载
   │  ├─ ReplayService.cs          # 记录回放
   │  └─ AutoSaveService.cs        # 自动保存调度
   ├─ Converters/
   │  └─ DataPointsToPointCollectionConverter.cs   # 折线图点集转换
   └─ ViewModels/
      └─ MainViewModel.cs          # 主业务逻辑
```

这种设计的核心思想是：

- **界面文件只负责展示和绑定。**
- **服务文件只负责一类业务。**
- **ViewModel 负责把界面和业务串起来。**
- **模型文件只负责描述数据结构。**

这样做的优点是后期加功能时更清晰，例如以后要增加 **Modbus、CRC16、报表导出、曲线缩放、多串口同时打开**，都可以继续按模块扩展。

## 二、如何用 VS2022 打开

1. 打开 **Visual Studio 2022**。
2. 选择 **打开项目或解决方案**。
3. 打开根目录下的 `SerialWorkbench.sln`。
4. 等待 NuGet/SDK 恢复完成。
5. 直接按 `F5` 运行。

> 说明：该项目使用 `net8.0-windows` 和 WPF，因此建议在 Windows 环境下编译运行。

## 三、每一步开发思路详细说明

### 第 1 步：先拆模块，再写代码

上位机软件最容易出问题的地方是把所有逻辑都塞进 `MainWindow.xaml.cs`。  
这样一开始看起来快，但后面维护会非常痛苦。

所以本项目先把功能拆成 5 类：

- **Models**：定义“数据长什么样”。
- **Services**：定义“功能怎么做”。
- **ViewModels**：定义“界面和功能怎么交互”。
- **Converters**：定义“界面可视化数据怎么转换”。
- **Views（MainWindow）**：定义“界面长什么样”。

这样用户要的“不同功能分为不同文件编写、模块化设计”就落实了。

---

### 第 2 步：先定义串口配置模型

串口通信最基础的是参数配置，所以先建立 `SerialSettings.cs`：

- `PortName`：串口号，比如 `COM3`。
- `BaudRate`：波特率。
- `DataBits`：数据位。
- `StopBits`：停止位。
- `Parity`：校验位。
- `Handshake`：握手方式，也就是硬件/软件流控制。
- `DtrEnable` / `RtsEnable`：控制握手线。
- `EncodingName`：文本接收时的编码方式。
- `SendHex` / `ReceiveHex`：发送/接收是否按 HEX 解释。

这样后面无论是连接、发送、还是保存配置，都统一从这个模型读取。

---

### 第 3 步：封装串口服务

`SerialPortService.cs` 是整个工程最关键的服务之一，它只负责串口层，不负责界面。

它做了 4 件事：

1. **扫描串口**：调用 `SerialPort.GetPortNames()` 获得当前系统中的串口列表。  
2. **连接串口**：把 ViewModel 中的配置写入 `SerialPort`，然后 `Open()`。  
3. **断开串口**：关闭串口，释放资源。  
4. **发送/接收数据**：
   - 发送时支持文本和 HEX。
   - 接收时从 `DataReceived` 事件里读取字节流。
   - 收发完成后统一转换成 `SerialDataFrame` 事件抛给上层。

这样做的意义是：

- 界面不用直接碰 `SerialPort`。
- 如果后面你要替换成 USB 转串口、自定义驱动、或 TCP 模拟串口，上层结构都不用大改。

---

### 第 4 步：定义原始帧和协议帧模型

上位机一般会同时处理两种数据：

1. **原始帧**：真实收发的字节流。  
2. **协议帧**：按设备协议解释后的业务数据。  

所以这里分成两个文件：

- `SerialDataFrame.cs`：保存时间戳、方向（TX/RX）、原始字节、显示文本。  
- `ProtocolPacket.cs`：保存协议头、命令字、长度、数据区、校验、是否有效、数值结果、说明文字。  

这样一来，日志显示和协议解析不会互相耦合。

---

### 第 5 步：封装协议解析服务

`ProtocolParserService.cs` 中示例实现了一个很常见的小型协议格式：

```text
AA + CMD + LEN + DATA + XOR
```

解析流程是：

1. 判断最少长度是否足够。  
2. 判断首字节是否为帧头 `0xAA`。  
3. 读取命令字 `CMD`。  
4. 读取数据长度 `LEN`。  
5. 从后面切出 `DATA`。  
6. 计算 XOR 校验并和报文中的校验字节比对。  
7. 若数据区前 1~2 字节可解释为数值，则进一步给可视化模块使用。  

如果你的设备协议不是这个格式，可以直接替换这个类，而不用改 UI。

---

### 第 6 步：做数据可视化

很多上位机不仅要“看到字符串”，还要“看趋势”。

这里专门增加：

- `DataPointModel.cs`：表示一个时间点和一个数值。  
- `DataPointsToPointCollectionConverter.cs`：把数值集合换算成 WPF `Polyline` 要用的点坐标。  

工作原理是：

1. 取最近一批数值点。  
2. 计算最大值和最小值。  
3. 根据画布宽高做归一化换算。  
4. 生成折线图。  

这样可以不依赖第三方图表库，也能先把功能做起来。后面如果你希望更专业，可以换 LiveCharts/OxyPlot。

---

### 第 7 步：做记录保存和回放

用户要求“自动或手动保存到文件”，所以这里拆成 3 个服务：

#### `RecordFileService.cs`
负责：
- 保存通信记录到日志文件。
- 从日志文件读取记录。

日志格式示例：

```text
时间|方向|HEX数据|预览文本
```

#### `AutoSaveService.cs`
负责：
- 按时间间隔自动保存。  
- 当前示例是“每分钟保存一次”。

#### `ReplayService.cs`
负责：
- 从历史记录中逐条重放。  
- 可以保持原始时间间隔，也可以快速播放。  

这样拆开的好处是：

- 保存逻辑、自动调度逻辑、回放逻辑互不影响。
- 后续加数据库、CSV、Excel、SQLite 都很好扩展。

---

### 第 8 步：用 ViewModel 串起来

`MainViewModel.cs` 是整个工程的“大脑”，但它不直接画界面。

它负责：

- 暴露所有绑定属性给界面：
  - 串口配置项
  - 日志列表
  - 协议解析列表
  - 可视化点集
  - 状态文字
- 暴露所有命令给界面：
  - 扫描串口
  - 连接
  - 断开
  - 发送
  - 手动保存
  - 载入回放
  - 清空数据
- 订阅 `SerialPortService` 的收发事件。  
- 在收到数据后：
  1. 更新日志显示。
  2. 调用协议解析。
  3. 提取数值并更新曲线。
  4. 根据开关执行自动保存。

这正是 MVVM 的核心：**ViewModel 协调 View 和 Service。**

---

### 第 9 步：设计 WPF 主界面

`MainWindow.xaml` 中把界面分成了几个清晰区域：

#### 左侧：配置与控制
- 串口参数配置。
- 串口扫描。
- 连接/断开。
- 发送区。
- 自动保存和回放控制。

#### 右侧 Tab：功能分区
- **数据收发**：显示原始收发日志。  
- **协议解析**：显示解析后的协议表格。  
- **数据可视化**：显示折线图和统计值。  

这样布局有两个好处：

1. 操作区和结果区分离，符合上位机使用习惯。  
2. 如果未来加“设备参数页”“报警页”“固件升级页”，可以继续加 Tab。

---

### 第 10 步：关闭窗口时释放资源

`MainWindow.xaml.cs` 中只保留了很少的代码：

- 创建 `MainViewModel`
- 设置 `DataContext`
- 在窗口关闭时调用 `Dispose()` 释放串口资源

这符合“界面代码尽量薄”的原则。

## 四、如何把它改成你真实设备协议

你后续只需要重点改 3 个地方：

### 1）改协议解析
修改 `ProtocolParserService.cs`：
- 把 `AA + CMD + LEN + DATA + XOR` 改成你的真实协议。
- 如果你用 CRC16/CRC32，就把校验算法替换掉。
- 如果你的数据有温度、电压、电流、状态位，就在这里拆字段。

### 2）改发送命令格式
如果发送不是纯文本或纯 HEX，而是按钮触发固定命令：
- 可以在 `MainViewModel.cs` 里增加更多命令按钮。
- 也可以单独新建 `CommandBuilderService.cs` 负责打包命令。

### 3）改可视化方式
如果你要显示多个通道：
- 可以把 `VisualizationPoints` 从单列表改成多通道集合。
- 再增加多个折线或更换专业图表库。

## 六、常见编译问题与解决办法

### 1. XDG0008：找不到 `DataPointsToPointCollectionConverter`

如果 VS 设计器提示找不到 `clr-namespace:SerialWorkbench.Converters` 下的转换器，通常不是 XAML 本身写错，而是 **项目里有 C# 文件先编译失败了**，导致设计器无法加载资源。

本项目里最容易触发连带错误的地方是：

- `AutoSaveService.cs` 里使用的 `Directory`、`Path`
- `RecordFileService.cs` 里使用的 `File`
- `MainViewModel.cs` 里使用的 `Path`

现在已经改为显式引用相关命名空间。如果你本地仍遇到这个问题，请先：

1. **清理解决方案**
2. **重新生成解决方案**
3. 关闭再打开 `MainWindow.xaml`

### 2. `Directory` / `Path` / `File` 不存在

如果报这些错误，通常说明当前项目没有正确识别到对应命名空间。现在代码中已经显式补上 `System.IO`，正常情况下重新加载项目即可。

### 3. `parts.Length`、`parts[0]` 一类错误

这类错误一般不是 `Split` 真有问题，而是前面的 `File` 未识别，导致后续类型分析全乱。只要 `System.IO` 恢复正常，`RecordFileService.cs` 中这些报错通常会一起消失。
